AI 看见 · 机械验实 · 人定性 · 全程留痕

同一条链路,在井盖、路面、灌溉管网三条业务线上走出三种不同形态。本页不讲故事,只给一张地图:上半页是三线 × 五阶段的机制矩阵,下半页是八个界面的实机缩览。任意一格点进去,就是它在原型里的真实位置。

贯穿全线 · 动作日志

平台一切行为以 对象-链接-动作 三类记录结构化存储;每一次动作(含规则引擎自动步)追加一条记录,带当时的规则包 / 参数集 / 模型 / 参考数据版本字段,可回放可导出。

贯穿全线 · 抽审兜底

凡绕过人的都进抽审队列:记账道 5% / 自动升格道 10% / 机械驳回 5% / 批量确认件 15% / 复验通过件 10%,时限 48h(全假设值,冷启动 × 2)。

贯穿全线 · 处置真源

处置状态以客户工单系统为准,巡检定性以本平台为准;不一致进对账队列,24h 内人工裁定(假设值)。

八个界面

六模块工作台 + 一个移动端 + 一个线索详情;缩览即实机,滚到即加载,点标题全屏打开
m1 复核工作台 →
三线分区队列 + 详情页:对象卡 / 证据卡 / 机械校验卡 / 动作面板 / 时间线。确认 / 驳回 / 升格在这里完成。
m1 详情 线索 CL-0417 →
主演件详情:机器直派并行复核、机械校验四项、复验人裁、主管紧急 override 与证据冻结。
m2 告警与工单 →
告警列表 · 工单镜像五格状态机 · 对账异常队列 · 调度视图(改派 / 合并 / 拆单,理由码必填)。
m2 调度 调度视图 →
班组负载卡与抢占调度:承接池无空闲时挂起在途养护单释放班组,紧急件完成自动回队。
m3 设施台账 →
资产库 + 归属;点位历史、证据链回查、观测覆盖窗、路面劣化曲线、Onwani 双语字段位。
m4 兜底与质量 →
抽审队列(来源标 / 拘审理由 / 48h 时限)+ 重复观测并入清单。自动化的对价记在这一页。
m5 统计总览 →
管理者三问:哪片最差 / 趋势如何 / 覆盖哪里有洞。数字实算自动作日志,不另编报表口径。
m6 系统管理 →
角色权限表(四角色 + 非人三账号)· 参数变更预演 · 类目机器直派开关(上级主管部门)· 值班表。
移动端 班组处置端 →
接单→到场→双照→完工,含拒单 / 受阻 / 安全 / 现场新增 / 交接。同点位重复观测由固定相机复扫触发,在工作台侧并入既有线索(见 m4)。

诚实边界

这份原型愿意把自己的边界写在正面。以下三条是全局口径,再往下 5 条是按设计文档《全场景流程图集》列出的浅演示场景——它们以详情页信息行或横幅形态呈现,不作为完整可点流程,但也不静默缺席。

时间是假时钟

不是真实时钟,只在「下一步」时步进。SLA 倒计时按场景步进变化,不按现实秒走。

没有后端

全部数据 mock 在前端 store(sessionStorage),刷新保留场景态;不调用任何 API,不发出任何网络请求。

零真实照片

所有证据图都是代码现场生成的 inline SVG 矢量示意,统一带「AI 生成示意」角标;数字带虚线下划线的均为假设值。
